Discovery should move from a single broadcast method to a layered strategy: 
first try subnet-aware UDP discovery (broadcast per active interface/subnet, 
not only 255.255.255.255), then fall back gracefully when LAN policies block broadcast. 
Add a small discovery state model (normal, degraded, manual-only) and expose it in UI so users understand what’s happening. 
Include stable peer identity in discovery/handshake payloads (deviceId, name, appVersion, capabilities) so peers can be recognized even if IP changes (DHCP), and so version/capability mismatches don’t break messaging.

Add a manual peer path as a first-class reliability feature: 
allow Add peer by IP[:port], validate, attempt handshake, and save successful entries as “Saved Peers” 
with reconnect/backoff probes. On app start, probe last-known peers from cache so users can reconnect 
instantly even if discovery is partially blocked. This gives you “always works” behavior across strict 
enterprise networks while keeping the app fully local and serverless.
